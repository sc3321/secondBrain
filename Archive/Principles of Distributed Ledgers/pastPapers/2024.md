1 Blockchain fundamentals a Consensus 

	i) Explain what determines block arrival times for Bitcoin, and separately for Ethereum. Which are more predictable and why? 

	BTC: timing depends on how quickly miners are able to solve the cryptographic problem of finding a nonce value to include in the block header below a target value. The BTC network can dynamically change this target value, increasing it if has taken a long time (relatively) since the last block. For Ethereum, it is more predictable as blocks arrive approximately every 32 slots (1 epoch) with this rate being more deterministic as it uses the PoS consensus algorithm where a proposer is chosen at random and all the other nodes attest to it with only the rare scenario of a party controlling 2/3 all staked ETH acting maliciously to stop this.

	ii) What is a state transition in the context of Ethereum, and what brings one about? Why is determinism important?

	 Ethereum can be described as a global-transaction-based state machine. State transitions are caused about transactions being included in a block and that block being proposed and validated by the other nodes of the network before being commited to the blockchain. The transactions all modify the world-state which is composed of Merkle-Patricia tries, which are compressed cryptographically secure data structures holding information about storage, code etc. for every single public address. After executing all the transactions which modify the different tries, the global state of network has been changed and the stateRoot which is an encapsulating signature of this worldState is included as the block header for the proposed block. Any false or discrepencies in the transactions and the final stateRoot is now DIFFERENT. Determinism is important as every validating block needs to be confident that it's final state root after executing all the transactions that the proposed block has made, will result in the same stateRoot.

	ii) In the context of Ethereum, explain what a transaction is. What types of transactions exist? What types of on-chain storage values can be updated by a transaction? 

	A transaction is any call to any contract that exists on the ETH network. Transactions are generally sent via an RPC which will be forwarded to the global mempool of nodes. These transactions have to be started by an EOA to provide gas-fees to facilitate any sort of transaction execution. A transaction can be a simple deposit to another EOA or to a contract or it can be a call to a smart-contract to execute something or call another smart contract. It can also be a scenario of deploying a new smart-contract.
	
	
	iii) Smart contracts on the EVM are immutable. How does the proxy design pattern work and how can it be applied to allow for upgradeability? 

	Proxies rely on the DelegateCall mechanism that a smart contract can implement. It basically means that when a call to a smartContract is made, the call can be delegated meaning the same execution code implemented on the smart contract can be executed from inside the proxy contracts storage environment. This allows changes to the proxy to not affect the underlying smart contract, keeping execution and storage logic separate. 
	

c Stablecoins and Automated Market Makers 

	i) Explain how overcollateralisation can be used by a non-custodial stablecoin to provide economic security. What is a minimum collateralisation ratio and what considerations should protocol designers take into account when setting this rate for a collateral asset? 

	When borrowing a volatile asset, for example ETH, a stablecoin is generally used as the means of collateral as it is unlikely to shift much in value. Overcollateralisation, protects the lender by forcing the borrower to pledge more than the stablecoin value of the borrowed asset, typically something like 150%. The minimum collateralisation ratio is what is the same as the liquidation threshold which is a multiplier on the overcollateralised assets such that the ratio of the collateral * multipler to the value of the assets in debt > 1. The more volatile the collateralised asset, the protocol designers should decrease the liquidation threshold to make the loan more sensitive to these volatile changes and protect themselves.
