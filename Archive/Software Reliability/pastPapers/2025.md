1 Consider the following C program:
        1 #include <stdio.h>
        2

        4   char a[7] = {2, 3, 5, 7, 11, 13, 17};
        5   unsigned x;
        6   scanf("%u", &x);
        7   printf("Prime number #%u is %d\n", x, a[x-1]);
        8 }

a You run the program and enter 9 from the command line. The program does not
crash. What is it likely to print?

It will print the second byte of what is stored in the address corresponding to x. Since x is directly adjacent to a in memory, x is effectively mapped to a[7,8,9,10] so it will print probably 0 since 9 is closer to the LSB or MSB so either a[7] or a[10] depending on endianness. 

b You run the program compiled with ASan and enter 8 from the command line.
ASan catches the bug. Briefly explain at a technical level how Asan achieves
this.

ASan introduces a mapping between program memory and its own shadow memory. It does this mapping at the granularity of 8 bytes at a time- could be more or less but 8 in general. It then is able to encode the addressability of each 8 byte chunk into either fully addressable [0], partially addressable [k] or not addressable [ < 0]. Between addressable memory objects it inserts 128 byte blocks of poisoned memory which is not addressable and uses this mechanism to detect unauthorised accesses.

2 Consider the following piece of code:

    1 #include <klee/klee.h>
    2 #include <stdlib.h>
    3 #include <assert.h>
    4
    5 int main(int argc, char** argv) {
    6   int i, n, *a;
    7
    8   assert(argc == 2);
    9   n = atoi(argv[1]);
    10  a = malloc(n * sizeof(int));
    11  klee_make_symbolic(a, n * sizeof(int), "a");
    12
    13  int r = 0;
    14  for (i = 0; i < n; i++) {
    15      if (a[i] > 10)
    16          r++;
    17      if (a[i] < 20)
    18          r++;
    19  }
    20
    21  if (r == 2 * n)
    22      abort();
    23 }

a How many paths are explored by KLEE in this program, as a function of n?
Assume that the compiler produces code that closely mirrors the C source code.

n^3- assuming optimisation over the fact that if a[i] is smaller than 10, there is no need to check if it is bigger than 20. So 3 paths per element of a, so n elements means that a can have n^3 possible combinations. 

b How many paths trigger the abort statement?

n paths.

For parts c) and d), suppose n is 5 and KLEE is configured to explore only 50
paths.

c Would running KLEE with the breadth-first search (BFS) heuristic trigger the
abort statement?

If my previous answer holds that the number of paths is something like 5^n, then we we land on 5^3 paths which is about 125 paths which is >> 50. As a result, BFS probably wont actually trigger the abort statement as there are precisely 5 paths that trigger the bug. BFS explores the state space incrementally, going in a step like manner through all possible paths. This 5 path scenario occurs at the end of precisely 5 iterations of the loop which is towards the end of the execution.


d Would running KLEE with the depth-first search (DFS) heuristic trigger the
abort statement?

Again while unlikely, there are more chances here as if the heurestic selects one of the first few conditions where a[i] > 10 && less than 20, it may continue this branch and on the next iteration of i + 1, it may select this path again and would have to do this precisely 5 times in a row to trigger the bug. DFS goes quite deep into program execution which is what is required to trigger the bug in this scenario.

AFL is a dumb grey box fuzzer, which usually uses branch coverage as the means of informing its mutation strategy. Since we have removed branches, and therefore removed the total branch coverage, the mutation strategies will not be as effective to reach LoC.
