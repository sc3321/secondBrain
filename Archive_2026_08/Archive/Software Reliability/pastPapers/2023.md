1a Can dynamic analysis tools report false positives? If so, give an example of such
a tool from the ones studied in the course and discuss when it can report false
positives. Otherwise, explain why not.

Particularly in the context of compiler fuzzing, there are situations where a dynamic analysis tool could lead to false positives. In the case of EMI based testing for instance, the tool may incorrectly modify portions of code in a program P causing undefined behaviour which when re-run expecting equivelent behaviour would give a different output. This difference in output would be interpretted as a bug but due to the incorrect mutations, it is actually a false positive.

c Consider a real-world project for which you need to create high-coverage inputs.


i) Why could it be impossible to achieve 100% branch coverage?

The inputs provided to the program may not be enough to cover all of the branch conditions. There may be some branch conditions which are based on external factors that the inputs would not be able to exercise.

Not sure, but the fact that the mutations are described as being weak, it is obvious to see that these mutations may not be sufficient to trigger different path or coverage execution in the program.


d Consider using ASan, EXE, KLEE and Valgrind (with the memcheck plugin) to
analyse a single execution path through a program. Answer the following
questions, justifying your answers:


i) Which tool(s) would you expect to be the fastest in general?

Asan is likely to be the fastest as it simply requires recompilation of the source code with some ASan instrumentation and loads the instrumented program onto the execution stack. Errors are caught immediately on the termination path and there is no need to invoke a solver at any point. Unlike valgrind which recompiles the code into its own binaries with instrumented code and also handles external libraries which it also instruments. The heavy additional instrumentation and also the recompilation into a different binary format makes ASan faster than valgrind.

ii) Which tool(s) would you expect to consume the largest amount of memory
in general?


Valgrind.
