1 Blockchain fundamentals

a Layer 1 blockchain design

  i) Explain how the design of blockchains (e.g., Bitcoin, Ethereum) ensures
data immutability.

  i.a) Every single block has a hash associated with it that has been calculated based on the current transactions and previous block hashes. To change a data value in a block, all the subsequent hashes must be recomputed for the entire chain.
  
  ii) How is the global/world state stored in Ethereum, and how do state
transitions occur?

  ii.a) World state is stored on the Ethereum blockchain. State transitions depend on the previous block to be added to the blockchain based on a Proof of Stake algorithm where random validators are selected to verify some transactions included in a block and the remaining validators attest to the validity of these proposed blocks. 
  
  iii) Explain how the gas system works in Ethereum. How does this mechanism
protect Ethereum against Denial-of-Service attacks (e.g., someone
deploying a smart contract to run infinite loops to take down the network)?

  iii.a) Gas is the currency of execution code which is included in transactions. Every instruction in a piece of code has an associated gas price, so an infinite loop would require an infinite gas price.

b Layer 2 rollups

  i) Explain what a Layer 2 rollup is.
  
  i.a) Moves computation and storage off chain. The L2 chain must inherit the security of the underlying l1 chain but is cheaper to execute transactions and for storage without all the meta-data etc.[check] 

  ii) Briefly explain how an L1 is used by an L2 rollup. Explain how using an
  L1 as a parent chain guarantees security, censorship resistance, and data
availability.

  ii.a) The L1 security features such as data-immutability are still existent in the L2 rollup. Every transaction that is part of the L2 chain must be guarenteed by the L1 base chain.

  ii) Explain the concept of a flash loan and how these are implemented on
Ethereum in terms of execution context.
  
  ii.a) An undercollareralised loan, which must be paid back within the same transaction. This last part is key, as it offers no risk to the lender of the flash-loan as if the amount is not paid back within the same transaction, then it will default and not allow the loan. Transactions etc. in Eth are atomic, so this can be enforced.

  iii) Ignoring the transaction fees, explain how block proposers can profit from the order of the transactions they include in a block. Provide an example of when and how a block proposer may do so

  iii.a) If the block proposer sees that there is a big upcoming deposit on an AMM due to something like a flash loan that would drive the price of the other product on the AMM very low, they can pre-emptively include a transaction to purchase that now temporarily very undervalued asset and exchange it on another PLF for a risk-free profit.
